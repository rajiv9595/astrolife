## 4. Rule-by-rule implementation summary

Shared canonical semantic (reused, not invented): **"lord strong"** mirrors
Lakshmi's `lagna_strong` — exalted / own / moolatrikona / Kendra-or-Trikona
occupancy / Shadbala ≥ 1.0. Same-house = conjunction (Budha-Aditya precedent).
Parashari aspects via `RuleContext` (special aspects included).

| Yoga | Implemented formation | Legacy delta (if any) |
|------|----------------------|----------------------|
| Akhanda Samrajya | Jupiter rules 2/5/11 AND (Jupiter or L2/L9/L11 in Kendra from Moon) | Union of the two documented readings; legacy used L2/L9/L11 only |
| Bhagya | L9 strong AND benefic in 9th | Legacy checked lord alone |
| Chamara | L1 exalted in Kendra AND aspects Lagna | Legacy omitted aspect |
| Chhatra | L5 strong | Strength def. broader than legacy (adds moolatrikona/trikona/shadbala) |
| Dhenu | L2 exalted | Exact |
| Gandharva | L10 in (3,7,11) + Sun dignity-strong + Moon in 9th | Sun: ex/own/MT vs legacy own/exalted |
| Go | Jupiter moolatrikona + same house as L1 | Legacy Go never fires (unhandled keys); canonical is formable (degree-gated MT, e.g. Sagittarius ≤10°) |
| Hara | Benefic in each of 4th/8th/9th from L7 | Exact |
| Hari | Benefic in each of 2nd/8th/12th from L2 | Exact |
| Jaladhi | L4 strong AND benefic in 4th | Legacy checked lord alone |
| Kahala | L4–L9 mutual Kendra OR both in Kendras (same-lord → lord in Kendra) | Legacy rule dead (unhandled `relationship` key; always INACTIVE) |
| Kalanidhi | Jupiter in 2/5 + same house as Mercury or Venus | Exact |
| Kama | L7 strong | Strength def. broader than legacy |
| Khyathi | L10 strong | Strength def. broader than legacy |
| Kusuma | Venus Kendra + Moon Trikona + Saturn in 10th | Exact |

## 6. Evidence implementation

Every rule emits structured `Evidence` from actual context facts
(`HOUSE_LORD_POSITION` with integer house values, `PLANET_DIGNITY`,
`PLANET_IN_HOUSE`, `KENDRA_TRIKONA`, `CONJUNCTION`, `ASPECT`,
`LORDSHIP_RELATIONSHIP`), each with `source` = ChartFacts/StrengthReport.
Central strength grading appends `PLANET_STRENGTH` evidence for FORMED yogas.
Verified: all 62 rules yield ≥1 evidence item on the golden chart; all carry
non-empty `source`; all FORMED golden yogas carry ≥2 items.

## 7. Provenance implementation

All 31 rules carry `Provenance` metadata (BPHS classical-text attribution,
`UNVERIFIED` reference per existing convention, per-rule `method`, variant
notes) and are registered in the existing `ProvenanceRegistry` at import via
`register_classical_yoga_provenance()` (idempotent; uses
`create_provenance_from_rule`). Verified: `ProvenanceRegistry.get()` resolves
all 31 new IDs; legacy IDs (`akhanda_samrajya_yoga`, `garuda_yoga`, …) resolve
to `None` — legacy fallback receives NO canonical provenance. Adapter exposes
`provenance.rule_id` per entry (e.g. VASI → `PARASHARI.YOGA.VASI`).

## 18. Known limitations

1. Canonical "lord strong" is intentionally broader than legacy (documented;
   causes Chhatra/Suparijata crosscheck deltas).
2. Akhanda/Kahala use documented disjunctive readings of classical variants
   (recorded in rule `notes`).
3. Go Yoga requires Jupiter inside its degree-gated moolatrikona range
   (e.g. Sagittarius 0–10°) per the canonical dignity engine — formable and
   tested, but rarer than a sign-only reading.
4. AI summary receives the first 12 yogas only (pre-existing behavior).
5. Legacy fallback entries do not carry canonical evidence/provenance (by
   design) and keep legacy shape + `_source` (pre-existing behavior).
